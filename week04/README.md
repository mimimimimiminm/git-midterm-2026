4주차 - 자동화와 협업

학습 목표
- 절대 경로와 상대 경로를 구분한다.
- `grep`, `find`, 파이프를 이용해 필요한 파일과 내용을 찾는다.
- 변수, 인자, 조건문, 반복문으로 작업을 자동화한다.
- 프로세스와 PID를 이해하고 프로세스를 확인하거나 종료한다.
- Git과 GitHub를 이용한 협업 및 병합 과정을 익힌다.
학습 내용

1. 반복 작업 자동화
반복되는 작업은 명령어와 반복문을 이용해 자동화할 수 있다. 예를 들어 다음 명령어는 디렉터리 100개를 순서대로 만든다.

```bash
for i in $(seq 1 100); do
    mkdir -p test/dir$i
done
```

2. 파일과 내용 검색
`find`는 조건에 맞는 파일이나 디렉터리를 찾을 때 사용하고, `grep`은 파일 안에서 원하는 문자열을 검색할 때 사용한다. 파이프 `|`를 이용하면 한 명령어의 결과를 다음 명령어에 전달할 수 있다.

```bash
find . -name "*.txt"
grep "error" app.log
ps aux | grep python
```

3. 프로세스와 백업
프로그램이 실행되면 운영체제에서 프로세스로 관리된다. PID는 각 프로세스를 구분하기 위한 번호이다. 프로세스 정보를 확인하고 필요하면 해당 프로세스를 종료할 수 있다. 또한 백업과 복원 작업도 명령어와 스크립트로 자동화할 수 있다.

4. Git과 GitHub 협업
여러 사람이 같은 프로젝트를 작업할 때는 브랜치를 이용해 작업을 분리하면 메인 브랜치를 안전하게 유지할 수 있다.

일반적인 협업 순서는 다음과 같다.

1. 브랜치 생성
2. 파일 수정 및 커밋
3. GitHub에 푸시
4. Pull Request 생성
5. 변경 내용 확인 후 Merge

```bash
git switch -c feature/my-work
git add .
git commit -m "작업 내용 추가"
git push -u origin feature/my-work
```

5. Conflict와 Merge
Conflict는 여러 변경 사항을 합치는 과정에서 Git이 자동으로 병합할 수 없는 상황이다.
충돌이 발생하면 해당 파일을 수정해 충돌 내용을 정리하고, 다시 커밋하고 푸시한 뒤 병합을 진행한다.
또한 `.gitignore` 파일을 사용하면 Git에서 추적하지 않을 파일이나 디렉터리를 지정할 수 있다.
